## Что получилось

Сделал сайт, на котором можно посмотреть доступность нескольких сайтов и результаты прошлых проверок. Данные хранятся в JSON-файлах в репозитории. Сам сайт собран на React и Vite и опубликован через GitHub Pages.

В списке сейчас GitHub, MDN Web Docs, Node.js, Vite и Википедия. Адреса находятся в `public/data/sites.json`, так что список можно поменять без переделки страницы.

## Выполненные требования

- На главной странице есть сводка по сайтам. Для каждого показаны название, адрес и результат последней проверки. Если результат есть, видно время ответа или причину ошибки.
- У каждого сайта есть своя страница. На ней показана история проверок с датой, состоянием и временем ответа или ошибкой.
- Есть страница «О проверке», где написано, как собираются данные и как часто идёт проверка.
- Для неизвестного адреса показывается страница с предложением вернуться к сводке.
- Страницы можно открыть по прямой ссылке и обновить. Для адресов используется часть после `#`, поэтому GitHub Pages отдаёт приложение и при обновлении вложенной страницы.
- Настроен GitHub Actions для ночной проверки. Его можно запустить вручную из вкладки Actions.
- Результаты сохраняются в `public/data/results.json`. После проверки сайт собирается и публикуется заново.
- Telegram-бот сообщает, когда сайт перестал открываться или снова заработал. Если состояние не изменилось, сообщение не отправляется. При первой проверке сравнивать ещё не с чем, поэтому она тоже не вызывает сообщение.

## Как работает проверка

Скрипт `scripts/check.mjs` берёт адреса из списка и по очереди отправляет запросы. На каждый запрос даётся до 15 секунд. Ответ с кодом от 200 до 299 считается успешным. Записываются время проверки, код ответа, время запроса и ошибка, если она возникла.

В файле результатов сохраняются последние 30 запусков, новые идут первыми. При следующем запуске скрипт сравнивает новый результат с предыдущим для каждого сайта. Если доступность изменилась, он отправляет сообщение в Telegram. Токен бота и ID чата хранятся в секретах репозитория, в коде их нет.

Расписание в Actions стоит на 21:00 UTC, это 00:00 по московскому времени. GitHub может запустить задачу с задержкой. После сохранения результатов отдельное задание собирает сайт и обновляет публикацию.

## Дополнительно

- История ограничена 30 проверками, чтобы файл результатов не рос бесконечно.
- В карточке и истории видно время ответа, а при ошибке код или сообщение об ошибке.
- Есть уведомления и о недоступности, и о восстановлении сайта.
- На сайте предусмотрено сообщение об ошибке, если файлы с данными не загрузились.

## Локальный запуск

Нужен Node.js. После клонирования репозитория выполнить:

```sh
npm install
node scripts/check.mjs
npm run dev
```

Адрес для открытия покажет Vite. Локальная проверка обновит файл результатов. Для отправки сообщений дополнительно нужны переменные окружения `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`. Если их нет, проверка сайтов всё равно выполнится, но сообщение отправлено не будет.

Для проверки сборки и кода:

```sh
npm run build
npm run lint
node --test scripts/notify.test.mjs
```

Тест проверяет, что уведомления выбираются при изменении доступности, а одинаковые результаты и первая проверка не считаются изменением.
